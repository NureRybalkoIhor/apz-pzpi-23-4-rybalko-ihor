3 ОПИС ВИКОНАНОЇ РОБОТИ
3.1 Загальний опис
FoodPreOrder — це інтегрована програмна система, розроблена для автоматизації процесів попереднього замовлення страв у закладах громадського харчування, клієнтського самообслуговування та адміністрування ресторанів. Головною метою системи є вирішення проблеми тривалого очікування замовлень клієнтами, збільшення пропускної здатності ресторанів у пікові години та оптимізація робочого часу кухарів і персоналу.
Система поєднує три ключові компоненти: мобільний застосунок для кінцевих користувачів (клієнтів), веб-портал для власників ресторанів, менеджерів та системних адміністраторів, а також REST API сервер, який забезпечує взаємодію з централізованою базою даних MS SQL Server. Серверна частина системи реалізована на платформі .NET 8 ASP.NET Core та підготовлена для локального запуску або розгортання в хмарі чи контейнеризованих середовищах.
Система забезпечує: перегляд меню та ресторанів у реальному часі, гнучке управління кошиком і замовленнями, рольове розмежування доступу для адміністраторів, бізнесу та клієнтів, моніторинг статистики продажів, резервне копіювання і відновлення даних, а також автоматичну генерацію конфігурацій для оркестрації та навантажувального тестування.
3.2 Реалізовані функції
Серверна частина забезпечує надійну автентифікацію та авторизацію користувачів на основі JWT-токенів, безпечне збереження паролів за допомогою алгоритму BCrypt та повне керування профілями з рольовою моделлю доступу. Реалізовано логіку для створення і налаштування ресторанів, категорій меню та страв із завантаженням зображень, обробку життєвого циклу замовлень від створення до готовності, збір аналітики та експорт статистики продажів у форматі PDF-звітів, а також інструменти резервного копіювання та відновлення даних системи через файли JSON.
Клієнтський мобільний застосунок надає інтерфейс для швидкої реєстрації та входу користувачів, зручного пошуку та перегляду списку доступних ресторанів і їхніх категорій меню. Користувачі мають можливість гнучко додавати та видаляти страви у кошику, оформлювати замовлення з автоматичним розрахунком вартості та відстежувати поточний статус приготування у реальному часі.
Адміністративна веб-панель реалізує повний кабінет управління для двох основних ролей. Для менеджерів ресторанів доступний функціонал додавання категорій меню, страв, редагування цін і описів та оновлення статусів поточних замовлень. Для системного адміністратора доступний моніторинг загальної статистики системи, керування ролями та блокуванням користувачів, резервне копіювання даних, а також панель генерації файлів оркестрації (Docker Compose, Kubernetes) та Locust-скриптів для тестування.
3.3 Не реалізовані функції
До переліку майбутніх інтеграцій та нереалізованого функціоналу входять: інтеграція з платіжним сервісом Stripe для проведення реальних онлайн-оплат; інтелектуальна система рекомендацій страв на основі попередніх замовлень; автоматичне прокладання маршрутів доставки з інтеграцією інтерактивних карт; ШІ-аналітика для прогнозування попиту залежно від сезону чи дня тижня; мультимедійний чат у реальному часі між клієнтом та персоналом ресторану; повна інтеграція з кухонними IoT-дисплеями для автоматичного трекінгу етапів приготування без ручного введення.
4 ВИСНОВКИ
Під час виконання лабораторної роботи було проведено повний цикл проєктування та програмної реалізації веб-клієнтського застосунку для платформи попереднього замовлення їжі FoodPreOrder. Основною метою роботи було створення повнофункціонального SPA, який забезпечує рольовий доступ для трьох категорій користувачів - клієнтів закладів, власників ресторанів із кухонним персоналом та системних адміністраторів - та безперебійну взаємодію із серверною частиною через RESTful API. У процесі розробки було застосовано сучасні підходи до побудови веб-застосунків, включаючи бібліотеку React 19 з TypeScript, збирач Vite 8, бібліотеку реактивного управління станом Zustand та фреймворк інтернаціоналізації i18next із підтримкою двох мов.
Ключовим етапом роботи стала реалізація рольового розмежування інтерфейсів із чіткою спеціалізацією кожного. Для ролі Customer було реалізовано повний цикл попереднього замовлення: каталог ресторанів із пошуком, меню із фільтрацією по категоріях, кошик із контролем кількості та вибором часу візиту, оформлення замовлення та оплата. Для ролей RestaurantOwner та KitchenStaff було побудовано бізнес-панель із чотирма функціональними модулями: інформація про ресторан, CRUD-управління меню (категорії та страви з двомовними назвами та завантаженням зображень через FormData), управління статусами замовлень та аналітичний дашборд із інтерактивними графіками на основі реальних даних (LineChart, BarChart, PieChart бібліотеки Recharts). Для ролі Admin реалізовано панель системного адміністрування з пошуком та фільтрацією користувачів, блокуванням/розблокуванням, зміною ролей та резервним копіюванням даних у JSON.
Важливим архітектурним рішенням стала побудова шару сервісів на базі axios із централізованими interceptors: request-interceptor автоматично додає JWT-токен до кожного запиту, а response-interceptor обробляє HTTP 401, виконуючи автоматичний logout та редирект. Такий підхід забезпечує єдину точку управління авторизацією без дублювання логіки у компонентах. Захист маршрутів реалізовано через компонент ProtectedRoute, який перевіряє наявність авторизації та відповідність ролі, забезпечуючи неможливість доступу до адміністративних або бізнес-сторінок без належних повноважень.
Підсистема інтернаціоналізації охоплює як статичний контент інтерфейсу (близько 160 ключів перекладу), так і динамічний контент бази даних (двомовні назви та описи сутностей). Форматування дат виконується через бібліотеку date-fns із автоматичним підбором локалі. Підтримка темної та світлої теми реалізована через CSS-змінні із миттєвим перемиканням без перезавантаження сторінки.
Отримана програмна реалізація повністю відповідає функціональним вимогам, забезпечує стабільну взаємодію із серверною частиною системи (ASP.NET Core API на порті 5082) та готова до демонстрації на захисті.
